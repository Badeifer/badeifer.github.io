The Dispatch

AI agents found a medical imaging zero-day in 11 minutes, and CISA gave you three days

Amazon caught attackers' Cairn agents breaking into a university server through an unknown MONAI Label bug. Here is how the agents did it, why the fix took four days to become installable, and what to check if you run MONAI Label.

CyberNovember 24, 20266 min read

A set of autonomous AI agents, pointed at university servers with the instruction "obtain shell access", found a bug nobody knew about in MONAI Label and used it to get root. Amazon Threat Intelligence published the details on 20 November, CISA added the flaw to its Known Exploited Vulnerabilities list on 23 November, and US federal agencies now have until 26 November to deal with it. If you or your lab runs MONAI Label, upgrade to 0.8.6 today; if you run anything else with an unauthenticated upload endpoint, this is the case study to show your boss.

MONAI Label is an open-source server from Project MONAI that helps researchers annotate medical scans with AI assistance. It is the kind of tool that gets installed on a GPU box in a research group, left on its defaults and forgotten. The flaw, now CVE-2026-133968 and rated 9.8 out of 10, lives in two upload endpoints, PUT /datastore/image and PUT /datastore/label. They build the destination path from a value the caller supplies and never check that the result stays inside the datastore folder. Authentication is off by default, so anyone who can reach the port can write a file anywhere the server process can.

How the agents got in

Amazon found the operation by accident, in the most fitting way possible. On 10 September its analysts spotted a publicly reachable instance of Cairn, an open-source framework that coordinates several AI agents to chase a goal written in plain language. Cairn was built for penetration testers. This copy had no login, so its whole history was readable: project settings, the operator's prompts in Simplified Chinese, and every step the agents took during a roughly 48-hour campaign that began on 8 September against universities in East Asia outside mainland China.

Against the MONAI Label server, the agents worked like a patient junior tester who never needs coffee. They identified the framework, listed its API endpoints, noticed an upload route that took a filename, and tried path traversal on it. It worked. Amazon puts the time from mapping the API to writing arbitrary files at about 11 minutes.

The escalation came in a later session and was neat. The agents wrote a Python reverse shell into sitecustomize.py, a file Python imports automatically every time an interpreter starts. Then they called MONAI Label's training endpoint, which spawns a fresh Python process. That process loaded the payload and phoned home as root.

Then a human stepped in. The operator handed the agents a proxy that tunnelled into a second university network, through a server running the same vulnerable software. Amazon infers the operator had already used the zero-day there, and directed the agents to work outward from it. Amazon attributes the activity, with moderate confidence, to a China-nexus actor, based on the prompt language, China Standard Time timestamps in scripts and the choice of targets.

The failures are the scarier part

Not everything worked. One operation spent about 16 hours and 148 consecutive actions trying to take over an exposed Redis database, cycling through replication abuse, sandbox escapes, config file writes and memory corruption, then pivoting to Log4Shell attempts, an SSRF in a neighbouring Qdrant vector database and credential sprays. Nothing landed. Another ran for more than six hours against a GPU server, building a list of about 80 real usernames from faculty pages, lab sites and papers, then trying more than 30,000 credential combinations across SSH, a VPN, a storage box and the campus portal. Also nothing.

An agent that fails for 16 hours straight costs its operator almost nothing, and it only needs to win once.

That is the real lesson. Human attackers get bored, sleep and prioritise. These agents ground through a hardened target overnight and moved on. Amazon's advice for defenders follows from it: favour high-confidence detections that trigger an automated response, with people reviewing outcomes rather than every alert, because a SOC that triages by hand is slower than an 11-minute exploit.

Why the fix was hard to install

The disclosure timeline has an awkward gap. MONAI Label's previous release, 0.8.5, shipped on PyPI in November 2024. The maintainers published their advisory on 18 November 2026, naming 0.8.6 as the patched version. But SecurityWeek and The Hacker News both reported in the following days that no fixed release was available to install, and PyPI shows 0.8.6 arriving on 22 November. For four days, the public had a precise description of a critical, exploited bug and only source code to protect themselves with.

The 0.8.6 release notes call it a security release that every server deployment should take. It also fixes a second, separate path traversal in session uploads.

What to do if you run MONAI Label

  1. Find it. Ask your research groups. MONAI Label tends to live on lab GPU servers and cloud VMs that central IT has never heard of.
  2. Upgrade to 0.8.6. Check with pip show monailabel, then upgrade from PyPI or pull the new Docker image.
  3. Turn on authentication. Set MONAI_LABEL_AUTH_ENABLE=True and do not hand the annotator role to people you do not trust. The advisory lists this as a workaround; it is also just good hygiene.
  4. Take it off the internet. Put it behind a VPN or an allowlist. A research annotation tool has no business on a public port.
  5. Run it as an unprivileged user with write access only to the datastore folder. Root was the prize here because the server had it to give.
  6. Hunt for signs. Look for a sitecustomize.py you did not put there, unexpected files outside the datastore, and odd calls to the training endpoint. Amazon published two addresses seen between 8 and 10 September: 142.4.98.145 and 142.4.107.34.

The bigger picture

For two years the argument about AI and offence has been about what models could do in a lab. This is a field report: an off-the-shelf, open-source agent framework, a one-line goal, and a fresh zero-day in software most security teams have never inventoried. Amazon notes that Gambit Security has documented a separate, money-driven crew using Cairn against online retailers, so this is not one group's toy. The bug the agents found was not clever. It was the ordinary kind that sits unexamined in niche research software for years, and that backlog is exactly what tireless, cheap attackers are built to work through.
